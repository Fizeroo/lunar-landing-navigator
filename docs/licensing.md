# Licensing and third-party materials

## Original project code

The inspected baseline commit154e54e contained a README and no established project license. The subsequent application was developed in this workspace with Claude/Codex assistance. No third-party application repository was copied. This is a preparation record, not a representation that the coordinator owns another person's copyright.

An unmodified **proposed Apache-2.0 license** has been saved in [licenses/Apache-2.0-proposed.txt](licenses/Apache-2.0-proposed.txt), retrieved from the [Apache Software Foundation](https://www.apache.org/licenses/LICENSE-2.0.txt). Before public release or competition submission, the project owner must confirm rights to the original content and adopt an OSI-compliant license with the correct copyright notice. Do not silently apply a new license to pre-existing or third-party material. No publication or submission was performed.

## Software dependencies

[third-party-materials.json](third-party-materials.json) records installed package versions, declared licenses and copied license/notice paths from the existing lockfile installation. It includes development packages and optional dependencies, not just browser-bundled code. The primary browser library three.js and its OrbitControls example carry MIT notices; Vite uses MIT, TypeScript Apache-2.0. Preserve the copied notices in `docs/licenses/` when distributing corresponding code. Native build dependencies require their own notice audit when distributing a build toolchain; any missing notice is reported in the inventory and must be resolved before that distribution.

## Data and imagery

NASA/JPL kernels, LOLA derived data, NASA SVS texture and IAU/USGS catalogue values retain their source attribution and usage conditions; they are not relicensed by the proposed code license. See [data-and-sources.md](data-and-sources.md) and dataset provenance. NASA branding does not imply endorsement. The [NASA media guidelines](https://www.nasa.gov/nasa-brand-center/images-and-media/) distinguish NASA-created material from third-party material and restrict implied endorsement and use of insignia. No NASA logo is used as the application's own logo.

## Verified competition requirements

The indexed official [2026 Participant Terms](https://www.spaceappschallenge.org/legal/), updated August7,2026, require suitable availability/licensing of original and third-party solution material, documentation of applicable licenses and citation of sources. They state an Apache-2.0 distribution default if no OSI license is specified. This does not prove the team owns all necessary rights. Full challenge Resources and authenticated submission fields could not be verified. See [submission-readiness.md](submission-readiness.md) for evidence boundaries and remaining actions.
